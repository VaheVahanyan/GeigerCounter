# GeigerCounter

Geant4 + ROOT модель прибора **РБМ** — телескоп из двух счётчиков Гейгера–Мюллера СТС-6
с алюминиевым фильтром между ними. Задача расчёта — эффективная площадь
`A_k(E, ϑ', φ')` двух каналов регистрации.

Каналы:

* `k = 1` — **верхний счётчик** (срабатывание верхней трубки, независимо от нижней);
* `k = 2` — **телескоп** (совпадение обеих трубок).

Оба канала считаются **в одном запуске**.

---

## Запуск

**Программу необходимо запускать из каталога сборки**: все пути к ресурсам заданы относительно него —
`../run.mac`, `../vis.mac`, `../Flux_config/<FluxType>_params.txt`, `../SEP_coefficients.CSV`,
`../TableSpectrum/*.csv`. Результаты (`.root`, `info_*.txt`, `post_processing/`) создаются там же.

```bash
cd cmake-build-release

# батчевый режим: пучок под углом ϑ' = 45°, φ' = 90°, только телескоп без коробки
./GeigerCounter -i ../run.mac -g telescope -f Uniform -fd flat --theta 45 --phi 90 -o run01 -t 8

# изотропный запуск (проверка интегрального отклика)
./GeigerCounter -i ../run.mac -g telescope -f Uniform -fd isotropic -o iso01 -t 8

# режим визуализации (Qt), выполняется ../vis.mac
./GeigerCounter
```

## Command Line Interface (CLI)

Единственный источник истины — разбор аргументов в `Loader::Loader` (`src/Loader.cc`).
Ниже перечислены **все** поддерживаемые флаги.

### Режим запуска

- `-i, --input <файл>`
  Путь к macro-файлу для батчевого режима (например, `../run.mac`).
  Если параметр указан, визуализация не запускается.
  Если не указан — запускается Qt-сессия с `../vis.mac`.

- `-noUI`
  Запуск без визуализации.

- `-t, --threads <N>`
  Число потоков. По умолчанию — число доступных ядер.

- `-o, --output-file <имя>`
  Имя выходного ROOT-файла; расширение `.root` добавляется автоматически.
  По умолчанию: `GeigerCounter`.

- `--bins <N>`
  Число бинов в выходных гистограммах по энергии. По умолчанию: `1000`.

### Геометрия

- `-g, --geom <вариант>`
  Вариант геометрии. По умолчанию: `full`.

  | значение    | что строится                                                           |
  | ----------- | ---------------------------------------------------------------------- |
  | `full`      | пенопластовая коробка + крышка + плата + 2 трубки + фильтр + держатели  |
  | `telescope` | 2 трубки + фильтр + держатели (без коробки, крышки и платы)            |
  | `single`    | только верхняя трубка + фильтр + держатели                             |

  `telescope` — рабочий вариант для расчёта `A_eff`: он даёт **оба** канала, `k = 1` и `k = 2`.
  `single` нужен только для оценки вклада второй трубки в отклик верхнего счётчика; в сетке сканирования он не участвует.

### Источник частиц

- `-f, --flux-type <тип>`
  Тип энергетического спектра. По умолчанию: `Uniform`.
  Доступно: `Uniform`, `Galactic`, `PLAW`, `COMP`, `Table`, `SEP`.

  Для расчёта `A_eff` нужен **`Uniform` с `is_log: 1`** — эффективная площадь не должна зависеть от спектра, спектр подставляется позже, при свёртке. Остальные типы полезны только для сквозных проверок.

  Диапазон энергий берётся из `../Flux_config/<Тип>_params.txt` (ключи `E_min:`, `E_max:`).

- `-fd, --f-dir, --flux-dir <режим>`
  Геометрия генерации частиц. По умолчанию: `isotropic`.

  | значение          | поверхность генерации                                    |
  | ----------------- | -------------------------------------------------------- |
  | `isotropic`       | сфера, косинусное распределение внутрь, полный `4π`      |
  | `isotropic_up`    | верхняя полусфера (относительно `+y`, оси телескопа)     |
  | `isotropic_down`  | нижняя полусфера                                          |
  | `flat`            | плоский параллельный пучок под углами `--theta`/`--phi`  |

- `--theta <градусы>`
  Зенитный угол `ϑ'` **в системе прибора**; полярная ось — `+y`, ось телескопа.
  Задаёт направление, **откуда** приходит частица. Используется только с `-fd flat`.
  По умолчанию: `0`.

  * `ϑ' = 0°` — сверху вниз вдоль оси телескопа (максимум канала совпадений);
  * `ϑ' = 180°` — снизу вверх;
  * `ϑ' = 90°, φ' = 0°` — вдоль оси трубок (с торца);
  * `ϑ' = 90°, φ' = 90°` — поперёк трубок (сбоку).

- `--phi <градусы>`
  Азимутальный угол `φ'` в плоскости `x–z`, отсчёт от `+x` к `+z`.
  Используется только с `-fd flat`. По умолчанию: `0`.

  При `φ' = 0°` или `90°` силуэт прибора — точный прямоугольник, и генерация идёт без потерь. При прочих `φ'` прямоугольник описан вокруг силуэта: нормировка остаётся
  верной, но часть частиц пролетает мимо. В `info_*.txt` печатаются обе площади, `S_perp` и `S_projected`, так что перерасход виден.

### Прочее

- `--save-secondaries`
  Дополнительно сохраняет ntuple `interactions` (вершины взаимодействий и вторичные частицы) и `event`. Заметно увеличивает размер выходного файла.

## Результаты запуска

* `<output>.root` — ntuple `edep` (`eventID`, `E0_MeV`, `edep1_eV`, `edep2_eV`), ntuple `primary`, гистограммы `genEnergyHist`, `trigEnergyHist`/`trigEnergyHistTel` и производные;
* `info_<detector>_<flux>_*.txt` — параметры запуска, состав газа, поверхность генерации, счётчики `N_1` / `N_tel`, эффективные площади, скорости счёта;
* `post_processing/<flux>_<частица>_<геометрия>_<направление>/`
  * `CSV/A_eff_<частица>_<геометрия>_<направление>.csv` — итоговая таблица
    `E_low, E_high, E_centre, N_gen, N_trig_1, N_trig_tel, A_1, dA_1, A_tel, dA_tel`
    с заголовком, где записаны геометрия, `ϑ'`, `φ'` и нормировка;
  * `CSV/edep.csv` — потери энергии по событиям (позволяет пересчитать порог офлайн);
  * `Histograms/*.png`.

`tools/merge_aeff.py` собирает CSV-файлы отдельных точек в одну длинную таблицу
`A_k(E, ϑ', φ')`.
